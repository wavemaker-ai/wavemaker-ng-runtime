# `stage-classic` run (2026-09-24) — separate from the `stage-ai` run above

Everything above describes the **`stage-ai`/WMS-32451** branch's Angular 22 upgrade. Those
commits are **not** in `stage-classic`'s history (verified with `git merge-base --is-ancestor`);
`stage-classic` was still on Angular 21.2.23 when this run started. The sections below are this

**several of its claims turned out to be wrong**, recorded below.

## Claims from the `stage-ai` run that this run disproved

| Claim (from `docs/22-upgrade.md` / pattern files / scripts) | What this run found |
|---|---|
| "ngx-bootstrap 22.0.0 natively ships all 5 patches `ngx-bootstrap-patch.mjs` applies" | **False.** 22.0.0's `PositioningService` is the same shape as 21.2.2 (bare `takeUntilDestroyed()` inside `runInZoneRootIfPresent`). The existing patch regex still matches and the patch is still required — verified by a live `node --input-type=module` regex test and by the patched bytes being present in both built bundles |
| §27a's "76 components got the pin" reads as if this repo already has it | That describes the *other* branch. On `stage-classic`, `grep -rl "changeDetection" projects/ --include="*.component.ts"` returned **0 of 74** — none of §27a/§27b/§27c/§7b had been applied here |
| `pattern-review.sh` / `verify-ngx-bootstrap-bundle.sh` INFO: "upstream does not use `__destroyRef` — patch may no longer be needed" | **Inverted logic.** Both scripts grepped upstream for `takeUntilDestroyed(__destroyRef)`, but `__destroyRef` is what the *patch adds* — upstream never contains it, so the check always printed "not needed" regardless of version. Both scripts fixed this run to match the bare `takeUntilDestroyed()` form instead |
| checklist.md §25's Section Version History row cited a "§25 body" describing the TS 6.0 `strict` exception | The §25 body never contained it. Closed this run by adding TS 6.0 rows (strict default flip, `ignoreDeprecations`, `TS2882`) plus an Angular-22 template-strictness row to §25's tables |
