## Validation 1 — Property registration (SC-001)

Confirm (e.g. via a quick console log in a scratch build, or by inspecting the registry after
`registerProps()` runs) that the `wm-form-group` registration Map now contains the AutoLayout keys
(`direction`, `width`, `height`, `position`, `padding`, `conditionalstyle`, …) alongside the
existing `captionposition`/`name`/`required`/`show`.

## Validation 2 — Prism gating & no-op at runtime (SC-004, FR-008)

- With `app.isPrism === false` (generated-app runtime): setting `direction`/`width`/etc. writes
  **no** inline layout style to the host — the composite renders exactly as before.
- With `app.isPrism === true` and the view initialized: the corresponding inline styles
  (`display:flex`, `flex-direction`, sizing, position) appear on the host.

## Validation 3 — Preserved behavior, zero regression (SC-005, FR-006)

Observe that the following continue to behave exactly as before (unchanged code paths):
- Default classes present: `form-group app-composite-widget clearfix`.
- Setting `required` sets it on the composite and propagates to child input controls.
- `captionposition` change toggles `caption-left`/`caption-right`/`caption-top`/`caption-floating`.
- `addForIdAttributes` runs in `ngAfterViewInit`.

## Validation 4 — Design-time behavior in Prism (SC-002, SC-003, manual)

In the studio (Prism) canvas after building the runtime (`build.sh` + yalc link):
1. Drop a Composite; leave layout props unset → renders exactly as today (caption-position layout).
2. Set `direction=row`, `gap=8`, `alignment=middle-left` → caption + control arrange via flex; flex
   overrides caption-position layout.
3. Set `width=fill`, `padding=8px`, `position=relative` → host is sized/positioned accordingly.
4. Preview / run the generated app (non-Prism) → the layout props have **no** effect; app renders
   as before.
